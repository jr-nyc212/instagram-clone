# Skill Smells: Fast Symptom-to-Cause Detection

**Purpose:** A scannable triage table for spotting a failing skill in seconds, *before* running the full audit. A "smell" is a surface symptom you can observe without instrumentation; each one points to a root cause and the reference that diagnoses it in depth. This is the 30-second pre-check — `references/anti-patterns.md` (AP-01 to AP-14) is the full diagnostic catalog, and `references/audit-rubric.md` is the scored evaluation. Use this file first; escalate to those when a smell trips.

This file does not re-prove the anti-patterns. It maps **what you notice** to **where to look**.

---

## How to use

1. Skim the smell tables top to bottom against the skill in front of you.
2. Each row you can answer "yes, that's happening" is a flagged smell.
3. Follow the **Go to** column for the diagnosis and fix.
4. Three or more smells in different categories → do not patch in place; run a full Eval-mode audit (`SKILL.md` §2) before shipping.

A skill can pass `scripts/validate.sh` (Level 1, structural) and still reek. Smells are behavioral and editorial — most are invisible to a deterministic validator.

## A. Triggering smells (the skill never fires, or fires wrong)

The description **is** the skill at runtime; a body nobody loads is dead capability [skill-md-frontmatter-as-discovery-trigger-primitive].

| You notice… | Likely cause | Go to |
|-------------|--------------|-------|
| You edited the body but not the description, and triggering "feels off" | Description drift — body and trigger surface diverged | AP-05; `references/decision-sequence.md` Detour 2 [description-based-workflow-routing-lazy-dispatch] |
| The description reads like a body summary ("This skill helps with…") instead of *when to use it* | Missing the what+when+capabilities structure; key use case not first | `references/audit-rubric.md`; [skill-description-structure-what-when-capabilities] |
| Two skills in the catalog share most trigger keywords | Overlapping descriptions → systematic mis-routing | AP-06 [agent-description-auto-dispatch-routing] |

## B. Sizing & attention smells (the body is bloated)

A verbose body dilutes attention on the lines that matter — measured at a 14–22% reasoning-token overhead and a ~3% success-rate drop from LLM-generated context files [context-file-instruction-bloat-eth-zurich].

| You notice… | Likely cause | Go to |
|-------------|--------------|-------|
| `wc -l SKILL.md` is over 500 | Body exceeds the hard cap; should split into `references/` | AP-04 [skill-as-directory-progressive-disclosure-three-levels] |
| Long inline blocks of pasted documentation or examples | Context copied instead of pointed-to | AP-07 [pointers-over-copies-in-context-files] |
| Rules that apply to almost no session sit in the always-loaded body | Instruction bloat; signal-to-noise problem, not a size problem | AP-08 [claudemd-as-signal-to-noise-problem-not-size-probl] |
| No short abstract at the top of the body | Missing L0 abstract — progressive-loading harnesses boot on it | `references/decision-sequence.md` Step 3 [skill-as-directory-progressive-disclosure-three-levels] |
| The body was auto-generated by an LLM and never trimmed | Auto-generated context-file bloat | AP-08 [context-file-instruction-bloat-eth-zurich] |

## C. Authoring-craft smells (the body fights frontier models)

| You notice… | Likely cause | Go to |
|-------------|--------------|-------|
| Explicit "think step by step", few-shot examples, or decomposition scaffolding in the body | Prescribed-reasoning anti-pattern — degrades GPT-5.4 / Claude 4.6 / Gemini 3.1 | AP-03 [reasoning-model-anti-pattern-prescribed-reasoning] |
| ALL-CAPS MUST / ALWAYS / NEVER with no WHY beside them | Rules stated without rationale; the model can't generalize them | AP-02 [skill-authoring-explain-the-why-not-musts] |
| Long lists of "do X, do Y, do Z" aspirations and few "do not" lines | Positive-aspiration overload; negative constraints collapse output space more reliably | `references/anti-patterns.md` [negative-constraints-as-probabilistic-output-collapse] |
| The skill encodes fully deterministic logic (parsing, math, formatting) in prose | Should be a script/code tool, not LLM prose | `SKILL.md` §0.5 [code-as-deterministic-tool-inside-skills][skill-vs-process-distinction-deterministic-rails] |
| The task is a single one-shot the base model already does | Should be a plain prompt, not a skill at all | `SKILL.md` §0.5 [skill-as-new-employee-mental-model] |

## Quick verdict

| Smells flagged | Verdict |
|----------------|---------|
| 0 | Clean enough to run `scripts/validate.sh` and proceed. |
| 1–2 in one category | Patch the specific smell; re-check that category. |
| 3+ across categories | Do not patch in place — run a full Eval-mode audit (`SKILL.md` §2 + `references/audit-rubric.md`) before shipping. |
| Any Category E smell | Block until resolved — safety smells are never "ship and fix later" [skill-security-audit-obligation]. |
